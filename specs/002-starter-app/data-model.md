# Data Model: Starter App

## Domain (feature `greeting`)

### PersonName (value object)

| Field | Type | Rules |
|---|---|---|
| value | string | trimmed; length 1–50 after trim; no control characters |

Factory `PersonName.create(raw)` returns the value object or throws `GreetingError`
(`code: NAME_EMPTY | NAME_TOO_LONG | NAME_INVALID`). Immutable.

### Greeting (entity)

| Field | Type | Rules |
|---|---|---|
| id | string | generated by an `IdGenerator` port |
| name | PersonName | |
| message | string | `"Hello, <name>!"`, built by the domain from `name` |
| createdAt | Date | from the injected `Clock` port |

Created only through `Greeting.create({ id, name, now })`. Immutable.

### GreetingError (business error)

Extends the shared `DomainError` (`code`, `kind: 'validation'`, English log-only `message`).
Codes are stable `SCREAMING_SNAKE_CASE`.

## Application

### Ports

- `GreetingRepository`: `save(greeting): Promise<void>`, `listRecent(limit): Promise<Greeting[]>`
  (most recent first, at most `limit`).
- Shared ports (in `shared/server/ports`): `Clock` (`now(): Date`), `IdGenerator`
  (`next(): string`).

### Use cases

- `greet({ name })`: validate (refuse with `GreetingError`), build the `Greeting`, save, return a
  `GreetingDto`.
- `listRecentGreetings()`: return up to `GREETING_HISTORY_LIMIT` `GreetingDto`s.

`GreetingDto` = `{ id, name, message, createdAt: string (ISO 8601) }`: the only shape crossing
the transport boundary.

## Infrastructure

- `InMemoryGreetingRepository` implements `GreetingRepository` (array, newest first).
- `SystemClock`, `RandomIdGenerator` (`crypto.randomUUID`) in `shared/server/adapters`;
  `FixedClock`, `SequentialIdGenerator` test twins exported from `testing.ts`.

## Transport

- Procedures `greeting.greet` (input `{ name: string }` validated by the shared zod schema,
  output `GreetingDto`) and `greeting.listRecent` (no input, output `GreetingDto[]`).
- Error mapping: `GreetingError` → oRPC `BAD_REQUEST` with `data: { code }`; anything else →
  `INTERNAL_SERVER_ERROR`, logged once with a `referenceId` returned to the client.

## Client state

- Route loader prefetches `greeting.listRecent` into the query cache.
- Form ViewModel (`useGreetingForm`): `useReducer` with states `idle → invalid | submitting →
  succeeded | failed`; submit is blocked while `invalid`; on success the `listRecent` query is
  invalidated; only the latest submission's result is applied.

## Configuration

Each owner declares its variables as an `EnvSpec` (`shared/server/config/env.ts`): the app-wide
spec `appEnv` lives there, a feature's spec lives in its `server.ts`, so deleting a feature deletes
its variables. The composition root calls `loadEnv(process.env, { <feature>: <feature>Env })`
once; it throws one `ConfigurationError` (`ENV_INVALID`) naming every missing or invalid variable
of every spec, never its value.

| Variable | Owner | Required | Rule | Default |
|---|---|---|---|---|
| `LOG_LEVEL` | app (`appEnv`) | no | `debug \| info \| warn \| error` | `info` |
| `GREETING_HISTORY_LIMIT` | greeting (`greetingEnv`) | yes | integer 1–100 | — |
